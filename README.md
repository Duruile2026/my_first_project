## 任务三：通用素养
### 1. 分支与合并
- 分支（Branch）：就像在主线任务里开了一个平行世界，你可以在里面随便改代码，不会影响正在运行的主线。
- 合并（Merge）：当平行世界里的功能测试好了，把它拉回主线，这就是合并。
### 2. 命令行用途
- `cd`：切换当前所在的文件夹。
- `ls`：列出当前文件夹里有哪些文件。
- `mkdir`：新建一个文件夹。
- `git add`：把修改的文件放入准备提交的暂存区。
- `git commit`：把暂存区的内容拍一张快照，记录到版本历史里。
- `git push`：把本地的提交推送到 GitHub 远程仓库。

### 4. 防“纯粘贴”承诺
- 1.随机布雷是怎么保证不重复的？
       布雷时用了一个 while 循环，条件是“已放的雷数 < 总雷数”。每轮在随机位置放一颗雷，如果这个位置已经有雷了，就跳过不放，继续下一轮。这样最终能保证放满 10 颗雷，而且位置不重复。
-  2. 数字格子是怎么算出周围有几颗雷的？
      每个格子会检查自己周围 8 个相邻格子（上下左右 + 四个斜角），数一数其中有几颗是雷，这个数字就显示在格子上。如果数字是 0，说明周围没有雷，程序会自动翻开周围 8 个格子，形成连锁展开。

  1.第一次点击一定安全：地雷是在你点第一下之后才随机放置的，并且会避开你点的那格及其周围 8 格，所以第一下必然连锁展开一片区域，不会一上来就炸。
  2.连锁展开用「栈 + 循环」而不是递归：避免递归层数过深，逻辑是「翻开一格 → 如果是 0 就把周围未翻开的格子压入栈」，直到栈空。

- 遇到的坑与调整：① 按左右键会误翻开未翻开的格子（真正的行为 bug） 浏览器在"左右键一起按"之后，仍会在你松开左键时补发一次 click。原来的代码没管它，所以对着一个没翻开的格子按左右键，会把它直接翻开——经典扫雷里这个手势只做"预备展开"，绝不会翻开未知格。
                 ② macOS / Linux 上按左右键会变成插旗（跨平台 bug） 这些系统上右键菜单是在松开右键那一刻弹出的，此时 event.buttons 的值是 1（左键还按着），不是 3。原来的判断只认 3，于是会把展开变成插一面旗（插错位置）。这个我在 Windows 上测不出来，是查事件规范时发现的。
                 改动：1.新增一个"手势开关":在全局变量里新加了一个开关，起名叫"是否左右键同时按"，初始状态是关闭。它的唯一作用：记住"这一次鼠标操作到底是不是左右键一起按的"，好让后面的左键点击知道该不该理睬自己。
                       2.左键点击处理里，先看一眼开关:在真正的"翻开格子"动作之前，插入了一次检查：如果开关是打开的，说明这次点击不是玩家真想点，而是左右键手势结束后浏览器补发的那一次——于是把开关关回去，然后直接结束，什么都不做，绝不翻开格子。如果开关是关着的，说明这就是一次正常的左键单击，照常去翻开格子。
这样一来，毛病①（按左右键把未知格翻开）就没了。
                       3.右键菜单处理里，放宽判断条件:原来这里的判断是"只有左右键都还按着，才算展开"，条件太严。现在改成"只要左键还按着（无论是左右键都按着，还是只按着左键），就算展开"，一旦成立就直接去执行展开并结束，不会再往下走。只有那种"纯粹的右键单击"（左键完全没参与）才会走到插旗/取消旗那一步。这样一来，毛病②（macOS/Linux 上按左右键变成插旗）就没了。
                       4.鼠标按下时重新记录开关:在"鼠标按键按下"的处理里，第一件事就是重新给开关赋值：左右键同时按着就置为打开，否则置为关闭。赋值之后，如果开关是打开的，就执行展开。放在第一件事做，是为了保证开关不会"残留"——每一次按下鼠标都会把它刷新一遍，绝不会出现"上一次的旧状态影响下一次操作"的情况。
